1. เพิ่มฐานข้อมูลสำหรับรองรับการแก้ไขหน้าเว็ปในส่วนของ adminwebsize เนื่องจากตอนdeployได้ทำการแก้ไขแล้วหน้าผู้ใช้ไม่อัพเดตวิธีมีประมาณนี้
    สร้างตารางใหม่ในฐานข้อมูล สร้างตารางฝห้ครอบครุมทั้ง 4 ส่วนโดยมี logo Brand Home Store Contact หน้าหลักของผู้ใช้ โดยจะเก็บค่าแก้ไขหน้าเว็บตรงadmin/website ให้เก็บพวกข้อความที่แอดใินปรับ 

    Brand & Header (logo) เก็บ รูปภาพโลโก้แบนรน์(Brand Logo Image)ที่อัปโหลดจากตัวเครื่องซึ้งเชื่อมกับตัวVercel BLOB ไปทำให้เก็บรูปได้เลย  ชื่อแบรนด์ (Brand Name) สโลแกนใต้โลโก้ (Brand Tagline) . คำอธิบายเกี่ยวกับแบรนด์ส่วนท้ายเว็บ (Footer About Description) 

    Brand Home เก็บ รูปภาพแบนเนอร์หลัก (Hero Banner Image)ที่อัปโหลดจากตัวเครื่องซึ้งเชื่อมกับ Vercel Blob ไปทำให้เก็บรูปได้เลย หัวข้อหลักตัวใหญ่ (Headline) คำบรรยาย / สโลแกนย่อย (Subtitle) ข้อความป้ายกำกับ (Badge / Tag) เลือกสินค้าที่ต้องการโชว์ในหน้าแรก (Featured Products) ตรงนี้ให้เก็บสินค้าที่แอดมินต้องการโชว์ให้ลูกค้าเห็น หัวข้อประจำส่วน (Section Title) คำบรรยาย / สโลแกนย่อย (Subtitle) ข้อความป้ายกำกับ (Badge / Tag)
    หัวข้อประจำส่วน (Section Title) คำอธิบายเนื้อหา (Description)

    หน้าสินค้า (store) เก็บ หัวข้อประจำส่วน (Section Title) หัวข้อประจำส่วน (Section Title) ข้อความเมื่อค้นหาไม่พบ (Empty Search Message)

    หน้าติดต่อเรา (Contact) เก็บ หัวข้อประจำส่วน (Section Title) คำอธิบายเนื้อหา (Description) ข้อความบนปุ่มกด (Button Text) หัวข้อประจำส่วน (Section Title) ที่อยู่ร้าน & สตูดิโอ (Address) เบอร์โทรศัพท์ติดต่อ (Phone) อีเมลติดต่อ (Email) และเก็บค่าเซตที่อยู่ api goolge map ที่แอดมินเซตที่อยู่ 

    ทุกอย่างที่ว่ามาเก็บพวกที่ซ่อนช่อง gird กับสลับตำแหน่ง gird ที่แอดมินเซ็ทไว้ด้วย เพื่อตอนdeploy ให้ผู้ใช้เห็นหน้าเว็บที่แก้ไขโดยแอดมิน

2. เก็บค่า status ตรงของข้อความติดต่อ ถ้าแอดมินไปกดปุ่มอ่านข้อความติดต่อที่ผู้ใช้inboxมา ตรงหน้าdashbord ตรงจำนวนข้อความที่ติดต่อที่ไม่ได้อ่านจะอัพเดตด้วย

3. ตรงเพิ่มสินค้าตรงส่วนข้องแอดมินให้กันไว้ไม่ให้ใส่ชื่อสินค้าซ้ำได้

4. หน้า Cotact ตั้ง Format บังคับตามนี้
        - เบอร์โทร บังคับให้เป็นเบอร์จริงใส่เลขมั่วๆไม่ได้
        - Email บังคับให้เป็นอีเมลจริงๆเช่น hotmail gmail

5. แก้api ไม่มี auth จริง login แล้วไม่ออก token, /api/admin/* ไม่มี middleware ใครก็ลบสินค้าได้ หน้าบ้านเช็กแค่ว่ามี cookie ชื่อนี้ไหม ปลอมได้
GET /api/contact เปิดสาธารณะ ข้อมูลลูกค้ารั่ว
login ใช้ or แปลกๆ, ilike ไม่ escape % และไม่มี rate limit
สร้าง ID ด้วย max+1 ชนกันได้และช้า → ใช้ serial/uuid
แก้/ลบสินค้าไม่ใช้ transaction พังกลางทางข้อมูลหาย
ดึง productDetail ทั้งตารางมา filter ใน JS
CORS * และส่ง error.message ดิบให้ client
route ปนกัน หน้าร้านสาธารณะเรียกผ่าน /api/admin/products

6. แก้ Db ตามนี้ ต้องแก้: email ยาวแค่ 25 ตัว (ควร 255), ราคาเป็น double (ควร numeric หรือสตางค์), ไม่มี createdAt/updatedAt, ไซส์เก็บเป็นข้อความ “7 UK”, ไม่มี stock, ไม่มี index บน FK และไม่มี unique ชื่อหมวด, รหัสตัวอย่างใน README ต้องไม่หลุดไป production
