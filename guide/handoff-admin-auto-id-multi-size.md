## 1. วัตถุประสงค์และการเปลี่ยนแปลงหลัก (Executive Summary)

ตามที่ได้รับมอบหมายให้ปรับปรุงระบบจัดการสินค้าและหมวดหมู่หลังบ้าน (`/admin/products`) ทางทีมพัฒนาได้ดำเนินการแก้ไขและทดสอบเสร็จสมบูรณ์ 100% ครอบคลุม 3 จุดหลักดังนี้:

| ลำดับ | หัวข้อความต้องการ | สภาพเดิม | สิ่งที่พัฒนาใหม่ |
| :---: | :--- | :--- | :--- |
| **1** | **รหัสหมวดหมู่ (Category ID)** | แอดมินต้องพิมพ์รหัส `cg_...` เองใน Input ทำให้เสี่ยงพิมพ์ซ้ำหรือผิดรูปแบบ | **สร้างให้อัตโนมัติ (Auto-generated)** โดยระบบจะคำนวณรหัสถัดไปจากเลขสูงสุดในฐานข้อมูล เช่น `cg_3` ทันที ช่องกรอกเป็น Read-Only พร้อม Badge สีเขียว "สร้างอัตโนมัติ" แอดมินพิมพ์แค่ชื่อหมวดหมู่แล้วกดบันทึกได้ทันที |
| **2** | **รหัสสินค้า (Product ID / `proId`)** | แอดมินต้องคอยดูหรือพิมพ์รหัสสินค้าเอง | **สร้างให้อัตโนมัติ (Auto-generated)** เช่น `pro_007`, `pro_008` แบบรันต่อเนื่อง 3 หลัก ป้องกัน Primary Key ชนกัน ช่องรหัสถูกล็อกเป็น Read-Only พร้อม Badge "สร้างอัตโนมัติ" |
| **3** | **การเลือกไซส์รองเท้า (Multi-Size Selection)** | เลือกรองเท้าได้เพียงไซส์เดียวในแต่ละครั้ง | **รองเท้า 1 ชิ้นสามารถติ๊กเลือกได้หลายไซส์พร้อมกัน** ในหน้า Add สินค้าและ Edit สินค้า โดยมี UI ชิปไซส์ UK ให้คลิกเลือก/ยกเลิก มีปุ่มทางลัด "เลือกทั้งหมด", "ไซส์มาตรฐาน (7-10 UK)", "ล้าง" พร้อมระบบสรุปไซส์ที่เปิดขาย |

## 2. รายละเอียดสถาปัตยกรรมและการทำงาน (System Architecture)

### 2.1 ระบบสร้างรหัสหมวดหมู่อัตโนมัติ (Auto Category ID)
- **Frontend Logic:**
  - เพิ่มฟังก์ชัน `getNextCategoryId(cats: CategoryItem[]): string` คำนวณหาเลขสูงสุดจากหมวดหมู่ที่มีอยู่ (เช่น `cg_1`, `cg_2` -> สูงสุดคือ 2 ดังนั้นรหัสถัดไปคือ `cg_3`)
  - เมื่อเปิด Modal "เพิ่มหมวดหมู่" ระบบจะตั้งค่า `newCategoryId` ให้อัตโนมัติ
  - ช่องกรอกใน Modal ถูกปรับให้เป็น `readOnly` และ `disabled` ไม่สามารถแก้ไขได้ พร้อม Badge `สร้างอัตโนมัติ` และเลื่อนเคอร์เซอร์ไปโฟกัสที่ช่อง "ชื่อหมวดหมู่" ทันที
  - เมื่อบันทึกสำเร็จ ระบบจะรีเฟรชรายการและคำนวณรหัสถัดไปสำหรับรายการต่อไปทันที
- **Backend Fallback (`POST /api/admin/products/categories`):**
  - แม้ Client จะไม่ส่ง `categoryId` มา เซิร์ฟเวอร์จะ Query หา `maxNum` จาก `categories` ในฐานข้อมูลและกำหนด `cg_${maxNum + 1}` ให้อัตโนมัติ ป้องกัน Error ทุกกรณี

---

### 2.2 ระบบสร้างรหัสสินค้าอัตโนมัติ (Auto Product ID)
- **Frontend Logic:**
  - เพิ่มฟังก์ชัน `getNextProductId(prods: ProductItem[]): string` คำนวณหาเลขสูงสุดจากรหัสสินค้าที่มีอยู่ทั้งหมดในระบบ (เช่น มี `pro_001` ถึง `pro_006` -> สูงสุดคือ 6 รหัสถัดไปคือ `pro_007`) จัดรูปแบบด้วย `padStart(3, '0')`
  - เมื่อคลิกปุ่ม **"add สินค้า"** ฟิลด์ `formData.proId` จะถูกกำหนดล่วงหน้าทันที
  - ใน UI Modal เพิ่มสินค้า ช่องรหัสสินค้าเป็น `readOnly` และ `disabled` พร้อม Badge `สร้างอัตโนมัติ` สีเขียว แอดมินไม่ต้องพิมพ์เอง ป้องกันความผิดพลาดจากการพิมพ์รหัสซ้ำ
- **Backend Fallback (`POST /api/admin/products`):**
  - หาก Body ไม่มี `proId` ส่งมา เซิร์ฟเวอร์จะคำนวณ `pro_${String(maxNum + 1).padStart(3, '0')}` จากตาราง `product` ให้อัตโนมัติ

---

### 2.3 ระบบเลือกรองเท้าได้หลายไซส์ (Multi-Size Shoes System)
โครงสร้างฐานข้อมูลรองเท้า SADIDA ถูกออกแบบให้ตาราง `product` มีความสัมพันธ์แบบ **One-to-Many** กับตาราง `product_detail`:

```
┌──────────────────────────────────────┐
│          product (สินค้า)            │
├──────────────────────────────────────┤
│ pro_id: "pro_007" (Primary Key)      │
│ pro_name: "Sadida Court King Pro"    │
│ price: 3290                          │
│ category_id: "cg_3"                  │
│ img: "/images/shoe_runner_1.jpg"     │
└──────────────────┬───────────────────┘
                   │ 1
                   │
                   │ N
┌──────────────────▼───────────────────┐
│     product_detail (ไซส์และสต็อก)    │
├──────────────────────────────────────┤
│ pdd_034 -> pro_id: "pro_007", 8 UK   │
│ pdd_035 -> pro_id: "pro_007", 8.5 UK │
│ pdd_036 -> pro_id: "pro_007", 9 UK   │
│ pdd_037 -> pro_id: "pro_007", 9.5 UK │
│ pdd_038 -> pro_id: "pro_007", 10 UK  │
└──────────────────────────────────────┘
```

#### ประสบการณ์ผู้ใช้บนหน้าจอ (UI/UX):
1. **Interactive Size Chips:**
   - ไซส์ UK มาตรฐาน: `6 UK`, `6.5 UK`, `7 UK`, `7.5 UK`, `8 UK`, `8.5 UK`, `9 UK`, `9.5 UK`, `10 UK`, `10.5 UK`, `11 UK`, `12 UK`
   - **เมื่อเลือก (Active):** พื้นหลังสีดำ ตัวหนังสือขาว มีไอคอนเครื่องหมายถูก `✓` พร้อมเงาสไตล์ Neo-brutalism
   - **เมื่อไม่เลือก (Inactive):** พื้นหลังขาว ขอบสีเทา ตัวหนังสือเทาเข้ม
2. **ปุ่มทางลัดด่วน (Quick Selection Buttons):**
   - `เลือกทั้งหมด`: ติ๊กทุกไซส์ตั้งแต่ 6 ถึง 12 UK ในคลิกเดียว
   - `ไซส์มาตรฐาน (7-10 UK)`: ติ๊กไซส์ยอดนิยม 7 UK ถึง 10 UK ทันที
   - `ล้าง`: ยกเลิกการเลือกทั้งหมด
3. **ระบบตรวจสอบความถูกต้อง (Validation):**
   - แสดง Badge นับจำนวนไซส์ เช่น `เลือกแล้ว 5 ไซส์`
   - กล่องสรุปรายการไซส์ที่เปิดขายด้านล่าง
   - หากแอดมินไม่ได้ติ๊กเลือกไซส์เลย (0 ไซส์) ระบบจะแสดงแถบแจ้งเตือนสีแดง: `⚠️ กรุณาติ๊กเลือกอย่างน้อย 1 ไซส์สำหรับรองเท้าคู่นี้` และบล็อกไม่ให้ Submit
4. **รองรับทั้ง Add Modal และ Edit Modal:**
   - เมื่อเปิด Edit สินค้าเดิม ระบบจะโหลดไซส์ทั้งหมดที่สินค้านั้นมีอยู่มาแสดงเป็นสถานะติ๊กถูกไว้ล่วงหน้า และแอดมินสามารถติ๊กเพิ่มหรือติ๊กออกได้อิสระ

## 3. สรุปไฟล์ที่ได้รับการแก้ไข (Code Modifications)

### 3.1 [`client/src/pages/admin/AdminProducts.tsx`](file:///d:/intern-basic-sadida/client/src/pages/admin/AdminProducts.tsx)
- **เพิ่ม Helper Functions:**
  - `getNextCategoryId()`: คำนวณรหัสถัดไปของหมวดหมู่
  - `getNextProductId()`: คำนวณรหัสถัดไปของสินค้า
- **ปรับปรุง State:**
  - `formData.selectedSizes: string[]` สำหรับเก็บชุดไซส์ที่แอดมินเลือก
- **เพิ่มฟังก์ชันการทำงาน:**
  - `toggleSizeSelection(size: string)`
  - `selectAllSizes()`
  - `selectPopularSizes()`
  - `clearAllSizes()`
  - `handleDeleteCategory(catId: string)`: แอดมินสามารถลบหมวดหมู่ที่สร้างขึ้นเองได้
- **เพิ่มคอมโพเนนต์ย่อย `renderSizeAndPriceSection`:**
  - คอมโพเนนต์ UI จัดการไซส์และราคาที่ใช้ร่วมกันทั้งหน้าต่างเพิ่มสินค้าและแก้ไขสินค้า
- **ปรับปรุง Modal UI:**
  - หน้าต่าง "เพิ่มหมวดหมู่ใหม่": รหัส ID เป็น Read-Only มี Badge "สร้างอัตโนมัติ"
  - หน้าต่าง "เพิ่มสินค้าใหม่": รหัสสินค้าเป็น Read-Only มี Badge "สร้างอัตโนมัติ" และแทนที่ Single-size selector ด้วย `renderSizeAndPriceSection()`
  - หน้าต่าง "แก้ไขสินค้า": ใช้งาน `renderSizeAndPriceSection()` รองรับการแก้ไขหลายไซส์
  - ตารางสินค้า: คอลัมน์ไซส์แสดงชิปไซส์ทั้งหมดของสินค้านั้นๆ (เช่น `8 UK`, `8.5 UK`, `9 UK`, `+2`)
  - หน้าต่างดูรายละเอียดสินค้า (View Modal): แสดงชิปไซส์ทั้งหมดที่วางจำหน่าย

### 3.2 [`server/src/routes/adminProducts.ts`](file:///d:/intern-basic-sadida/server/src/routes/adminProducts.ts)
- **`POST /api/admin/products/categories`:**
  - ตรวจสอบ `categoryId` หากไม่มีให้คำนวณ `cg_${maxNum + 1}` อัตโนมัติ
- **`DELETE /api/admin/products/categories/:id`:**
  - Endpoint สำหรับลบหมวดหมู่สินค้า
- **`POST /api/admin/products`:**
  - รองรับการ auto-generate `proId` หากไม่ได้ระบุมา
  - คำนวณ `prodetailId` (`pdd_XXX`) จาก `maxDetailNum + 1` ป้องกัน Primary Key ชนกัน
  - วนลูป insert ทุกไซส์ที่อยู่ในอาร์เรย์ `sizes: string[]` เข้าตาราง `productDetail`
- **`PUT /api/admin/products/:id`:**
  - รองรับการอัปเดตไซส์ผ่าน `sizes: string[]` โดยลบไซส์เดิมและเพิ่มชุดไซส์ใหม่ลงตาราง `productDetail`

## 4. ผลการทดสอบระบบ (Verification & Testing Results)

1. **การคอมไพล์ Frontend (`client`):**
   ```bash
   bun run build
   ```
   - **ผลลัพธ์:** `✓ built in 263ms` (ผ่าน 100% ไม่มีข้อผิดพลาด TypeScript)
2. **การทดสอบสร้างหมวดหมู่อัตโนมัติ:**
   - ส่ง Request สร้างหมวดหมู่โดยไม่ระบุ `categoryId`:
     ```json
     { "categoryName": "รองเท้าบาสเก็ตบอล" }
     ```
   - ได้รับผลลัพธ์ `categoryId: "cg_3"` ทันที
3. **การทดสอบสร้างสินค้าพร้อมหลายไซส์อัตโนมัติ:**
   - ส่ง Request สร้างสินค้าใหม่โดยไม่ระบุ `proId` พร้อมไซส์ `['8 UK', '8.5 UK', '9 UK', '9.5 UK', '10 UK']`:
     ```json
     {
       "proName": "Sadida Court King Pro",
       "categoryId": "cg_3",
       "price": 3290,
       "sizes": ["8 UK", "8.5 UK", "9 UK", "9.5 UK", "10 UK"]
     }
     ```
   - ระบบสร้างสินค้า `pro_007` สำเร็จ พร้อมผูก 5 ไซส์ใน `product_detail` ครบถ้วน
4. **การทดสอบลบสินค้า:**
   - คำสั่ง `DELETE /api/admin/products/pro_007` ลบข้อมูลสินค้าและไซส์ที่เกี่ยวข้องเรียบร้อย
